Что мы автоматизировали (SIS2, SIS3, SIS4, Journaling)
1. Journaling (SIS5 core component)

Сделано:

Journald переведен на persistent storage:

Логи сохраняются на диск, не пропадают после перезагрузки

Docker интегрирован с journald:

Теперь все контейнеры пишут сюда, а не в overlay

Включен auditd и добавлены audit-правила:

отслеживается изменение конфигов SSH

изменение sudoers

доступ к shadow

journalctl summary собирается и логируется через Ansible

Польза:

Централизованный логинг

Возможность расследовать инциденты

Аудит изменений

Устойчивая ретенция логов

Снижение хаоса в лог-файлах

2. SIS2 — Access management

Сделано:

Созданы группы: admins, auditors, automation, postgres_grp, web

Созданы пользователи: admin1, auditor1, autobot, pguser, webuser

Настроены права:

auditor может читать системные логи

autobot может рестартовать nginx без sudo-пароля

Польза:

Ролевая модель доступа

Никаких ручных операций на сервере

Пользователи создаются детерминированно

Полностью IaC (infrastructure-as-code)

3. SIS3 — Go system daemon

Сделано:

Go установлен

Проект создан автоматически

Бинарник собран

Создан systemd service

Сервис включен и запущен

Польза:

Твой сервис запускается на постоянной основе

Перезапускается автоматически при сбое

Стартует после ребута сервера

4. SIS4 — Dockerized microservice

Сделано:

Проверка Docker

Создание директории проекта

Копирование Go исходников

Создание Dockerfile

Сборка Docker image

Остановка старого контейнера (если был)

Запуск нового контейнера

Польза:

Микросервис задеплоен корректно

Не нужен ручной docker build/run

Обновления воспроизводимы

Zero manual steps
